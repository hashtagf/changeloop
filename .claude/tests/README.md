# Foundation deterministic tests

**Audience:** Change Loop maintainers and coding agents working in this upstream
repository. This suite is not installed into consumer projects and is not a
user's checklist for proving their application.

These tests verify the shipped OpenSpec-native control plane. They do not spend
model tokens and do not test an application generated by Foundation.

## Choose a starting point

| What you are doing | Check |
|---|---|
| Repairing one behavior | Run the nearest existing regression; find its owner in [Current suites](#current-suites) |
| Finishing a related batch of edits | Inspect `run-all.sh --affected --list`, then run `run-all.sh --affected` |
| Preparing the final change for commit | Run the default `run-all.sh` gate: every suite except the `SLOW` tier and the exclusive benchmark (about two minutes); `--quick` is the same gate |
| Checking everything CI checks | Run `run-all.sh --full`: every suite, including the slow tier. CI runs it on every push and pull request as four parallel `--shard K/4` jobs, and it must be green before merge or release |
| Preparing a release candidate | Run `run-all.sh --release`: the full gate plus the release-only `openspec native sentinel` (the release workflow runs this form) |
| Editing documentation | Run `docs/run-doc-consistency.sh`; build `website/docs` if site pages changed |
| Investigating a timeout | Read the failing suite output and duration; use `FOUNDATION_TEST_JOBS=1` to isolate concurrency effects |

Run commands from the repository root, with the required `rtk` prefix:

```sh
rtk test bash .claude/tests/run-all.sh --affected --list
rtk test bash .claude/tests/run-all.sh --affected
# Local pre-commit gate (fast tier):
rtk test bash .claude/tests/run-all.sh
# Complete set, as CI runs it:
rtk test bash .claude/tests/run-all.sh --full
# Release candidate (full gate plus the release-only sentinel):
rtk test bash .claude/tests/run-all.sh --release
```

The documentation suite also runs `docs/documentation-governance.test.mjs`:
entry-guide links and fragments, first-run reading budgets, complete website
locale pairing, and the pointers to the canonical
[documentation policy](../../CLAUDE.md#documentation-ownership).
These structural checks complement semantic review; they cannot establish that
every explanation is correct or that a translation preserves its meaning.
It also runs `docs/feature-map.test.mjs`: every CLI command, slash command,
user state, and runtime group belongs to exactly one feature in
`docs/feature-map.json`, every named path exists, and `docs/feature-map.md`
matches what `scripts/docs/feature-map.mjs --write` renders.

## Setup and execution

The entrypoint is also run by `.github/workflows/workflow-tests.yml` as
`run-all.sh --full --shard K/4` (four parallel jobs whose slices together are
the whole `--full` set; a newer push cancels the run it supersedes) and by
`.github/workflows/release.yml` as `run-all.sh --release`. `--shard K/N` deals
suites slowest first in a snake order, so each slice gets a share of the slow
tier; `--list --shard K/N` prints one slice.

Run `npm ci --ignore-scripts` in the test workspace before the full suite.
`run-all.sh` and the shared `lib/assert.sh` drop the host session's
`CLAUDE_PROJECT_DIR`, `CLAUDE_FOUNDATION_PROJECT`, and identity, phase, and
guardrail `FOUNDATION_*` variables, so a run started from an agent shell tests
its fixtures, not the caller's project and policy; runner controls
(`FOUNDATION_TEST_*`, `FOUNDATION_SUITE_TIMEOUT_SECONDS`, shards) stay. A suite
that needs one of those variables sets it inline on the command under test.
When the benchmark suite is selected, the runner checks for `c8` before launching
suites, so a missing dependency fails during setup instead of after a long run.

For an edit/repair loop, `run-all.sh --affected` selects the suites that own
the changed files plus their proof, review, Land, and mutation dependencies.
With no changed files it exits without running a suite. Use
`run-all.sh --affected --list` to inspect the selection without executing it;
the two flags may appear in either order. The selector reads added, modified,
renamed, deleted, staged, unstaged, and untracked paths; set
`FOUNDATION_TEST_BASE=<ref>` to include committed changes since a branch point.
It is deliberately conservative: changes to the composition root, protocol,
runtime version, CLI router, workspace policy, or shared test libraries expand
to the full suite set. Affected selection includes `SLOW` suites whose owned
files changed, so a local installer edit still runs the installer suite. Plain
`run-all.sh` remains the local gate before commit and `--full` in CI the
complete one, so affected execution cannot silently weaken Land evidence.

The two tiers are one list: `SLOW` in `run-all.sh` names the real-Git
end-to-end, mutation, installer, and topology suites that each take over a
minute on a loaded machine. The default gate leaves them (and the exclusive
benchmark) out to fit about two minutes on a 14-core workstation; `--full`
and `--release` run them first in the pool. `EARLY` names the longest
default-tier suites, which start next so none begins late. Move a suite into
`SLOW` only when its measured duration threatens that budget.

Suites run concurrently — each builds its own fixture under `mktemp -d`, so
nothing orders them — and their output is buffered and replayed in table order,
so a parallel run reads and diffs exactly like a serial one. Mutation suites use
`lib/mutation-fixture.sh` to copy the runtime and detector into private source
trees before injecting faults. They therefore run in the same pool without
exposing the checkout or another suite to a mutant, and interrupted or
overlapping runs remove only their temporary trees. The pool runs one worker
per logical core (at most 16), because most suites already fan out into Node
and Git children; the longest suites start first so none of them stretches the
tail of the run. Set `FOUNDATION_TEST_JOBS=1` to force fully serial execution
when bisecting. The workload suite runs once, inside `openspec native
sentinel`; it is not registered as a separate row. The sentinel is
release-only: plain `run-all.sh` and `--full` leave it out (it adds about six serial
minutes), `run-all.sh --release` adds it, and `--affected` still selects it
when benchmark manifests, tasks, fixtures, or the workload suite change. The
sentinel and the benchmark run alone after the pool: their frozen oracles carry
fixed timeouts that a loaded pool can exceed.
The default watchdog is 300 seconds per suite, 600 seconds for the long
suites (the real-Git pull request delivery suite, the proof loop, apply
conflict, concurrent repositories, the topology siblings row, and the installer
suite, about two minutes alone and over five on a loaded CI runner), and 1200
seconds for the topology/planning row (once a single fixture of 163 assertions
that made only 110 of them in 600 seconds on the macOS CI runner; its
independent setup, copy, and sibling fixtures now run as the `topology setup`
and `topology siblings` rows).
`FOUNDATION_SUITE_TIMEOUT_SECONDS` overrides all of them. A suite the watchdog
kills always counts as failed and is reported as `(timed out after Ns)` in the
failure list and the tail header; the kill stops the tree child first, so the
suite's own last assertions and summary can otherwise read like an ordinary
failure.

Every suite runs with stand-in `claude` and `codex` executables first on PATH
(the real-model guard), so no fixture can reach a paid host model. Readiness
probes (`claude auth status`, `codex login status`, `--version`, `--help`,
`codex doctor`) get a deterministic "not logged in/unavailable" answer, which
the topology planning rows rely on; any other call is refused and fails the
suite with `real-model guard: suite "<label>" invoked a real model CLI`. A suite
that needs a model CLI must put its own fake earlier on PATH or point the
fixture at an absent executable. `run-run-all-control-tests.sh` proves both.

## Evidence views

Three wrappers restate suites above as TAP so a provider can check a discovered
count against a `minimum` floor. They are deliberately absent from `run-all.sh`,
which needs only an exit code — running them there would execute the same
assertions twice.

| Wrapper | Restates |
|---|---|
| `harness/run-changeloop-seam-tap.sh` | Change-loop seams, phase mutation guard, workspace surface, context budgets |
| `harness/run-review-gate-tap.sh` | Review and acceptance protocol, provenance, waiver policy, attempt-chain integrity |
| `harness/run-sandbox-seam-tap.sh` | Shared contract slices (sandbox creation and setup, apply, Land, multi-repository) plus the wiring contract |
| `docs/run-docs-tap.sh` | Documentation contracts and context budgets |

A wrapper adds no assertions of its own. Add the assertion to the underlying
suite, where a human reading `run-all.sh` output will also see it.

`interview/` holds the deterministic question-replay self-test and its live
replay probe; `bench/` holds the OpenSpec-native benchmark (see its README).

## Add a regression

`user-decisions.test.mjs` runs with advance lifecycle outcomes and covers spec
approval, shared review deadlines, explicit decision routes, and waiver expiry;
`target-edits.test.mjs` beside it covers target-checkout edits made outside
the sandbox while shell mutations are audited, `session-lease.test.mjs`
covers the harness-held lease for a session Build task, and
`task-change.test.mjs` covers why a task with no change in its paths is handed
back and the routes it names.

Put a regression at the lowest deterministic boundary that caught the defect:

- runtime or evidence semantics → `harness/run-harness-tests.sh`;
- install/upgrade/CLI semantics → `harness/run-installer-tests.sh`;
- state a published 3.7.0 consumer holds → `harness/run-upgrade-from-3.7-tests.sh`;
- shipped hook behavior → `hooks/run-hook-tests.sh`.

Run focused checks during repair and the default `run-all.sh` gate before
handing off a harness change; CI runs `--full`. See [Choose a starting point](#choose-a-starting-point).
